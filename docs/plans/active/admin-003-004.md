# Plano: operação de jobs e auditoria administrativa

- Status: implementado nesta branch; correção de revisão aplicada, aguardando nova revisão/PR
- Spec: [identidade e administração](../../specs/identidade-e-administracao.md)

## Critérios de aceite

- [x] Platform admin/support consulta saúde paginada de jobs de importação e recorrência sem payload.
- [x] Jobs `failed`/`dead` elegíveis podem retornar a `pending` com retry idempotente, motivo e step-up; outros estados/tipos são rejeitados.
- [x] O contexto de plataforma não depende de `app.workspace_id`: RLS permite leitura a `platform_admin`/`platform_support` e retry de import/recorrência somente a `platform_admin`.
- [x] O retry valida o identificador UUID na borda HTTP e o step-up aceita TOTP ou código de recuperação.
- [x] Auditoria administrativa é consultável por ator, alvo, ação e intervalo UTC, paginada e limitada à retenção de 365 dias.
- [x] Correlation IDs e erros são exibidos sem conteúdo doméstico ou payload de job.
- [x] As páginas web cobrem carregamento, vazio, erro/permissão/offline, sucesso e feedback de retry.

## Evidência

Contratos, serviço, adapter PostgreSQL, rotas e testes focados cobrem os critérios acima. A migration `0023_platform_job_scope` ajusta somente as políticas RLS existentes: `job` já possui estado/lease/idempotência/correlation ID e `platform_audit_event` já possui os metadados exigidos. O teste PostgreSQL descartável cobre jobs de importação e recorrência sem contexto de workspace; ele é executado quando `DATABASE_URL_TEST` está configurado.
