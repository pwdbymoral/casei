# Plano: DATA-002/003 — parser, mapeamento e preflight

- Status: ativo
- Spec associada: [intercâmbio de dados](../../specs/intercambio-de-dados.md)
- Arquitetura: [núcleo de intercâmbio](../../architecture/intercambio-de-dados-csv.md)

## Objetivo

Completar o núcleo puro de importação com uma representação tabular comum para
CSV e XLSX, leitura segura de uma única planilha XLSX sem executar fórmulas,
perfis de mapeamento serializáveis e preflight reutilizável por ambos os
formatos. Nenhuma função deste slice acessa storage, banco, sessão ou aplica
linhas.

## Estado inicial

`@casei/data` já possui parser RFC 4180, normalização/mapeamento editável,
parsers pt-BR/en-US, fingerprints escalares e preflight por linha para CSV.
Ainda não há parser XLSX nem contrato de perfil de mapeamento. A spec exige
XLSX sem macros, uma planilha por operação, limites de 10 MB/50 mil linhas/256
colunas/1 MB por célula e valores de fórmula somente pelo cache armazenado.

## Abordagem

- preservar `parseCsv` e sua API compatível;
- introduzir `ParsedTabular`/`TabularRow` e aceitar essa forma no preflight;
- adicionar `parseXlsx` usando ExcelJS `4.4.0`, com validação do contêiner ZIP
  antes do load, cabeçalhos locais, inflação real com limite rígido, rejeição de
  VBA/links externos e limites de expansão;
- converter células para strings sem avaliar conteúdo; fórmulas sem resultado
  armazenado serão erro acionável; números fora da precisão decimal segura serão
  rejeitados para evitar arredondamento silencioso;
- adicionar perfil de mapeamento nomeado, imutável e validado, sem persistência;
- cobrir Red→Green para workbook válido, sheet selection, macros/links,
  fórmulas, limites, perfis e preflight comum.

## Rastreabilidade

- CSV existente + `csv.test.ts`: RFC 4180, encoding/locale, mapping, linhas e
  fingerprints.
- XLSX novo + `xlsx.test.ts`: formato, sheet única, cache de fórmula,
  macro/link, limites, inflação real, tamanhos ZIP inconsistentes e precisão
  numérica.
- Perfil novo + testes: sugestão editável reaplicável sem arquivo original.
- Preflight comum: resultado por linha, duplicata apenas como sugestão e erro
  antes de qualquer aplicação.

## Riscos

- ExcelJS materializa o workbook; o scanner ZIP valida cabeçalhos locais e
  infla cada entrada com `maxOutputLength` antes do load. O limite de
  linhas/colunas é reaplicado ao modelo. Números sem lexema XML são aceitos
  apenas dentro da política conservadora de precisão segura.
- Fórmulas podem não ter cache; rejeitar esse caso evita cálculo silencioso.
- A API de perfil é deliberadamente pura; persistência e autorização ficam em
  DATA-001/DATA-004/DATA-006.

## Decisões durante a implementação

- A arquitetura vigente separa storage/jobs/UI do núcleo. O parser XLSX fica
  no mesmo pacote puro porque esta fatia precisa entregar CSV/XLSX à mesma
  prévia; nenhum adapter de arquivo persistente é introduzido.
- ExcelJS `4.4.0` foi escolhido após consulta à documentação/repositório
  oficial: oferece leitura de workbook a partir de buffer e declarações TypeScript.
